# Specialized Engineering toolchains

Use only the selected skill in the native task brief. Work within the authorized project, offline. Do not run upstream installers, update checks, publishers, agent configuration changes, browser launchers, server commands or hardware integrations. No global skill activation. Requirements and native Kanban remain authoritative; diagrams are dated explanatory snapshots.

- Architecture: use Archify directly: `node renderers/TYPE/render-TYPE.mjs input.json output.html`, then `node scripts/check-render-output.mjs output.html`. These registered renderer/checker entry points avoid the outer CLI subprocess launcher, which fails with EPERM in the validated Codex sandbox. Browser verification is performed by the controller separately. Do not use upstream `deliver`/`finalize`, browser launchers or update paths. The controller supplies evidence; do not claim an upstream finalize receipt. Keep editable JSON and HTML, label native IDs/revisions and proposed nodes explicitly.
- Technical mechanism: copy the closest Anatomy example build script into the project, adapt it, and reference the pinned kit and inline-kit by absolute paths from the task context. Write standalone HTML into the project. Keep the build script. No gallery publishing or live browser driving.
- CAD: use the private Python and build123d for the editable parametric model. Use public `cad.build123d.is_sound`, `topology_errors` and `mass_properties([(solid, density), ...])` on the resulting solid. Export with build123d's STEP/STL functions, reopen STEP, compare dimensions/volume and write the measured results. This is the text-to-cad Python integration, not its daemon/viewer. Do not call `cad run`, start its server, auto-install extras, print or fabricate. Keep a callable `build()` and explicit dimensions in millimetres; include independent checks and source.
- Blender: use the pinned Blender binary with `--background --factory-startup --disable-autoexec --threads 2 --python-exit-code 1 --python SCRIPT`. Follow the modeling/export/rendering and asset QA skills, import reviewed helpers if useful. Scripts/imports/assets stay in the project. Produce editable `.blend`, `.glb` and a small CPU render where supported. Reopen files in background to verify. Do not start MCP servers, install addons, use personal preferences or enable network/GPU devices.

The native single Engineering writer bounds heavy work. Tasks remain cancellable through the existing Project Map; no child may detach or survive its task. Report blockers with precise missing inputs. A generated file or successful process exit does not prove its requested geometry or behavior.

When an HTML bundles upstream JavaScript or fonts, retain its LICENSE, NOTICE and third-party/font license files beside the project artifact. Use the pinned kit files; do not infer every bundled asset license from the repository license.

## Permissions and broker implementation

The pilot uses Hermes's native plugin registration and tool dispatch. There is no replacement agent loop, routing model, memory store or task scheduler. Hermes's native session database and memory remain authoritative. The broker's separate SQLite ledger records **capability proposals/grants**, not conversations or task ownership.

The broker runs outside the agent's Bubblewrap namespace. The agent receives only its Unix socket. It cannot see the grant database or the controller's grant method. A proposal binds the relative path, complete content, expected previous file hash and digest. Only the external controller grants it. Apply rejects extra arguments, a different digest, a changed target and reuse. The grant is spent before the effect, so an interrupted apply is not automatically replayed. The harness verifies the resulting file outside the agent process; model prose is not evidence.

Filesystem access uses directory file descriptors and no-follow opens, rejects traversal/absolute paths/symlinks, and bounds reads and proposals. The fixture is mounted read-only in the agent; the external broker performs the authorized write. ARGOS, user projects, personal Codex data and pilot controller credentials/ledger are absent from the namespace. The namespace also isolates process visibility and temporary files. Configuration, plugin code and skills have read-only mounts. Native memory/session data remain writable.

The **effective** tool list is identical for CLI and Desktop:

`argos_read`, `argos_propose`, `argos_apply`, `memory`, `skills_list`, `skill_view`, `skill_manage`.

Broker tools are advertised only when the broker health check succeeds. General has no enabled terminal, browser, execute-code, plugin/catalog installation, delegation, cron, computer-use or desktop-action tool. Native skill inline shell and lazy dependency installation are disabled. Skill/code directories are read-only. Manual approvals and deny-on-unattended settings are configured; the broker never delegates authorization to an LLM classifier. Background memory review and metrics upload are disabled.

An actual inspection found that Desktop folds in `catalog` automatically. The pilot now disables that toolset explicitly; inspecting only the CLI allowlist would have missed `manage_catalog`. Native Tool Search also rejected an attempt to recover the disabled terminal tool. [Actual effective surfaces and tool results](effective-surface.json).

The offline negative suite covers unapproved apply, agent self-approval, mutated payload/digest, replay, changed target, absolute/traversing/symlink reads, hidden personal/source/controller paths, direct and child-shell writes, configuration/plugin/skill mutations, `/proc/1/root` traversal, network egress, disconnected clients, a second broker owner, skill traversal and Tool Search escalation. An exclusive process lock prevents multiple broker owners; grant consumption also uses a database compare-and-set. See [machine-readable checks](validation.json), [broker audit](broker-audit.jsonl), [test controller](../checks/validate.py).

**Limits:** these are finite tests of a deliberately small surface. They are not an audit of arbitrary third-party plugins or every upstream tool. Offline tests use a private network namespace. Online Codex tests use shared networking so the supported client can authenticate/infer; outbound destinations and host loopback are not filtered. The native runtime can access its own pilot authentication store; credential isolation from every possible in-process plugin is not established. Other plugins and General execution tools remain disabled. A production security gate needs an explicit egress/credential policy and tests for each newly enabled host capability.

## Decision and remaining gates

**No full migration.** Keep this isolated pilot and operational ARGOS separate. The evidence supports further evaluation of Hermes's native facilities, not replacing a working product now.

Before a migration decision:

1. Supply an explicitly unbilled/free-tier provider credential and test the native General tool loop, the full ARGOS interaction contract, ES/EN continuity and sustained quota/latency. Do not infer free-provider quality from subscription Codex.
2. Specify production egress, credential and per-capability execution boundaries; test each enabled shell/browser/plugin/desktop route against them. Connect real ARGOS host adapters only after those boundaries are reviewable.
3. Validate mixed General/Engineering ownership and recovery using native Hermes facilities, with disposable candidates and observed effects.
4. Decide whether the native HUD/SDK can implement the required orb under Hyprland with an acceptable footprint. Verify compositor permissions and Windows separately.

No duplicate general runtime, parallel memory/task ownership system, operational migration, billing activation or automatic update was introduced.
